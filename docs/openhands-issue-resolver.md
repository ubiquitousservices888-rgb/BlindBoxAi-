# Owner-triggered OpenHands issue-to-draft-PR workflow

**Status:** PROPOSED. No Gemini execution, repository secrets, GitHub deployment, or end-to-end production run has been verified by this document.

**Scope:** This is a small alternative to the legacy OpenHands Resolver reusable GitHub workflow, which is no longer on current OpenHands `main`. It instead uses the [OpenHands Software Agent SDK](https://github.com/OpenHands/software-agent-sdk) directly. Owner-created GitHub issue labels (`fix-me`) and owner comments beginning `@openhands-agent` invoke `.github/workflows/openhands-resolver.yml`. It handles exactly one issue per run. Repository owner must trigger it; labels/comments from other accounts are skipped.

**Setup:** In GitHub repository **Settings → Secrets and variables → Actions**, add `LLM_API_KEY` (Gemini API key from an eligible free-tier-only project), `LLM_MODEL` (`gemini/gemini-2.5-flash` or `gemini/gemini-2.5-flash-lite`) and `PAT_TOKEN` (fine-grained repo token with Contents: Read/Write, Pull requests: Read/Write, and no workflow-administration or external-account permissions). Review repo Settings → Actions to permit creating PRs if required by repository rules. No key values belong in issues, README files, shell output, logs, or commits. Free-tier usage is subject to quotas, availability, project billing settings, data-use terms, and GitHub Actions billing; **$0 is not guaranteed**.

**Safeguards:** Separate steps isolate tokens. During AI file edits, only `LLM_API_KEY`/`LLM_MODEL` are present; `PAT_TOKEN` is not passed to the agent or npm tests. No `TerminalTool` is enabled. A trusted validator copied from the original commit checks all modified paths and budgets before testing, and rejects changes to GitHub workflows, Supabase, API routes, AGENTS.md, approval/affiliate/payment/publishing paths, and other protected files. The agent is capped at 12 iterations, and runs have an overall timeout. After `npm run qa:unit` passes, a fine-grained token opens a **draft PR**, never a merge. Failure attempts to post a plain-English issue comment. Browser, integration and production proofs are separate release gates. Review every PR before granting permission for further stages.

**Security caveats:** Even though the agent has only file-editing/task tools, an LLM provider receives issue text, and AI-generated source can be malicious. Do not place secrets in the repository, issue text, or agent input. Review untrusted changes and build logs before merge. Do not use this agent for protected paths; those require the repository's existing owner-gated review and disposable end-to-end test protocol in `AGENTS.md`.

**Verification:** Python syntax, YAML structural parsing, and disposable git diff guard PASS in preparation. Full SDK installation, Gemini API execution, GitHub Actions validity, repository CI, and actual draft PR creation are UNVERIFIED until the workflow is reviewed and executed with owner-controlled credentials.
